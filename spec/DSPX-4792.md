# upstream(opentdf/tests): native go/java/js adapters; delete the cli.sh shims

## Summary
Blocked by the otdf-adapter protocol ticket (A1).
Steps A2-A6: replace each bash shim with a native Python adapter, one SDK at a time, then delete the shell.
Strangler, not big bangFour external repos pin opentdf/tests@main (opentdf/platform, web-sdk, java-sdk, otdfctl). cli.sh must keep working until the last lane migrates.

What moves out of bashFlag translation. Three divergent vocabularies become three small methods instead of a cross-cutting shell problem: go space-separated (--host, --attr, --with-client-creds '{json}'), java =-form (--platform-endpoint=, --encap-key-type=, --policy-type=), js camelCase (--assertionVerificationKeys, --policyEndpoint, --policyBinding ecdsa). Quirks like go's mv "${3}.tdf" "$3" ("go helpfully adds a tdf extension") become one line in go.py.
Version gates become data.
GATES = {
  "go": {
    "ecwrap":             MinVersion("0.12.0"),
    "kas_allowlist":      HelpContains("decrypt", "--kas-allowlist"),
    "autoconfigure":      Always(True),
    "gmac_root_rejected": Unprobeable("no CLI surface"),
  },
  ...
}One evaluator, three data tables, real semver comparison. Version detection stays per-adapter (.sdk_version vs .version vs .["@opentdf/sdk"]) as one method each, rather than a jq pipe in every case arm.
Latent bug this surfaces: go's hexless gate compares $2 >= 2 under a comment claiming 4.3.0. Only visible once the comparison is data instead of awk. Fix it as part of A3 and note the behaviour change.
Binary resolution moves to install time. otdf_sdk_mgr.installers.install_go_release already writes a .version file that the shims re-parse at runtime (module@ver -> go run, bare tag -> legacy module path, absent -> @latest) and copies cli.sh/otdfctl.sh/opentdfctl.yaml into dist/<version>/. Replace with a descriptor written once:
{"sdk": "go", "version": "v0.31.0", "adapter": "go",
 "exec": ["go", "run", "github.com/opentdf/platform/otdfctl@v0.31.0"]}That deletes the runtime re-derivation, the three cp lines in each sdk/*/Makefile, and — critically — sdk/go/cli.sh:174, which locates the suite root by walking parents for a pyproject.toml containing name = "xtest" so it can source test.env. Python already knows all of that. Keep .version readable for one release as a compat shim.
sdk/go/otdfctl.sh (39 lines — the policy-admin wrapper otdfctl.py shells out to) re-implements the same resolution plus the same test.env walk-up; collapse it into a PolicyClient on the adapter.

[ ] grep -rn 'cli\.sh' xtest/ returns nothing.

[ ] tdfs._uncached_supports's 10-case Python match is gone, folded into the gate tables.
[ ] Skip counts for a full run are unchanged, except any change caused by fixing the hexless gate — which must be called out explicitly in the PR description.
[ ] setup-cli-tool/action.yaml shrinks to "resolve versions + otdf-sdk-mgr install".
