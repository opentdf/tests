# upstream(opentdf/tests): native go/java/js adapters; delete the cli.sh shims

## Summary

Workstream A steps A2–A6 of DSPX-4640: replace `xtest/sdk/{go,java,js}/cli.sh`
with native Python adapters implementing the `SdkAdapter` protocol from
DSPX-4791, one SDK at a time, then delete the shell.

846 lines of bash across the three shims, of which **388 (45.9%) are the
`supports` case statement** — a hand-rolled feature-detection language built out
of `grep` against `--help` text and semver comparison written in `awk`. It
encodes **60 feature gates** over 78 possible (SDK, feature) pairs; the other 18
fall through a `*` arm to `exit 2` and are read as "unsupported". A further 13
pairs are answered in Python before the shell is ever invoked, by a `match`
statement in `tdfs.SDK._uncached_supports`. Two of those 13 contradict or
duplicate the shell.

This is a strangler migration, not a rewrite. Four external repos pin
`opentdf/tests@main` (`opentdf/platform`, `web-sdk`, `java-sdk`, `otdfctl`), so
every shim keeps working until its lane has run green on both paths.

**This PR is stacked on DSPX-4791** and lands none of the adapters. It lands the
safety net they need: a committed characterization snapshot of all 78 gates
(`xtest/supports_matrix.json`) and an offline test module that holds the
snapshot and the shell to each other (`xtest/test_supports_matrix.py`). The
staged adapter work in A2–A6 is specified below.

## Problem / Motivation

`cli.sh` is three programs pretending to be one interface. They share a name, a
verb vocabulary (`encrypt`, `decrypt`, `supports`), and an `XT_WITH_*`
environment-variable contract with `tdfs.py` — and nothing else. Each one
independently re-derives which binary to run, re-implements semver comparison in
`awk`, re-invents feature detection by grepping help text, and translates the
harness's uniform keyword arguments into its SDK's private flag vocabulary.

Four concrete costs:

**Feature detection is unreviewable.** A gate like

```bash
"${cmd[@]}" --version --json | jq -re .schema_version \
  | awk -F. '{ if ($1 > 4 || ($1 == 4 && $2 >= 2)) exit 0; else exit 1; }'
```

is a semver comparison, but nothing about it reads as one. You cannot diff the
go gate against the java gate for the same feature without mentally executing
both. So they drift, silently, and they have: see the two divergences in
[Edge Cases](#edge-cases--constraints). The awk form also fails open — POSIX
specifies a *string* comparison when a field is not a numeric string, so
`main`, `dev`, and `v0.12.0` satisfy every `$1 > 0` gate in the suite.

**Logic is split across two languages with no single source of truth.** Whether
`go` supports `autoconfigure` is answered by `cli.sh:41` (`exit 0`) *and* by
`tdfs.py:899` (`return True`). Whether `js` supports `key_management` is
answered by `cli.sh:83` (`>= 0.8.0`) and then overridden to `False` at
`tdfs.py:896` for exactly `v0.2.0`. Six more pairs are answered only in Python,
because the shell has no arm at all and the `*` default would say "no". A reader
asking "does this SDK support X?" has to know to check both files.

**The gates hide in prose.** 4 feature probes live *outside* the `supports`
blocks, inline in the encrypt/decrypt argv paths, where they select between two
flag spellings (`--platform-endpoint=$PLATFORMURL` vs `=$PLATFORMENDPOINT`) or
append a flag conditionally. They are the same `help | grep` pattern, they are
not registered anywhere, and an adapter that ports only the `supports` block
will emit different argv and the A2 diff gate will go red.

**Binary resolution is re-derived at runtime.** `otdf_sdk_mgr.installers` writes
a `.version` file at install time; each shim re-parses it on every single
invocation to decide between `go run module@ver`, a legacy module path, and
`@latest`. `sdk/go/cli.sh:174` locates the suite root by walking parent
directories looking for a `pyproject.toml` containing `name = "xtest"`, so it
can `source test.env`. `sdk/go/otdfctl.sh` (39 lines) duplicates both the
resolution and a *subtly different* walk-up. Python already knows all of this.

## Proposed Solution

### The gate table is the migration

Each shim's `supports` block becomes a data table on its adapter, evaluated by
one shared evaluator from DSPX-4791. Five gate kinds cover 74 of 78 pairs; the
remaining 4 need one composite.

| Kind | Meaning | Count |
| --- | --- | --- |
| `HelpContains(subcommand, needle)` | run `help <subcommand>`, search output | 24 |
| `MinVersion(spec)` | parse a version probe, compare semver | 15 |
| `Always(bool)` | a fact about the SDK, not about the build | 11 |
| `Delegate()` | ask the binary; it self-reports | 4 |
| `Unprobeable(bool)` | no CLI surface exists; asserted with a reason | 3 |
| `AllOf(HelpContains, MinVersion)` | `ecwrap`, all three SDKs | 3 |
| *(no arm — `*` → `exit 2`)* | becomes an explicit `Always(False)` or an override | 18 |

`AllOf` is the one addition to the DSPX-4640 kind list. `ecwrap` needs it on all
three SDKs: the flag exists in help output before the implementation is correct,
so the shell checks help *and* a floor version. Modelling it as two independent
gates would lose the conjunction.

### Flag vocabulary

Three divergent CLI vocabularies become three small `build_argv` methods instead
of a cross-cutting shell problem:

| Concept | go (space-separated, kebab) | java (`=`-form, kebab) | js (space-separated, camel) |
| --- | --- | --- | --- |
| platform address | `--host $PLATFORMURL` | `--platform-endpoint=$PLATFORMURL` | `--policyEndpoint $PLATFORMURL` |
| client credentials | `--with-client-creds '{json}'` | `--client-id=… --client-secret=…` | `--auth $CLIENTID:$SECRET` |
| attributes | `--attr a,b` | `--attr=a --attr=b` | `--attributes a,b` |
| assertion keys | `--with-assertion-verification-keys` | `--with-assertion-verification-keys=` | `--assertionVerificationKeys` |
| ecwrap | `--wrapping-key-algorithm` | `--encap-key-type=` | `--encapKeyType` |
| policy binding | *(n/a)* | `--policy-type=` | `--policyBinding ecdsa` |
| KAS allowlist | `--kas-allowlist` | `--kas-allowlist=` | `--ignoreAllowList` |
| spec version | `--target-mode` | `--with-target-mode=` | `--tdfSpecVersion` |
| container | positional `ztdf` | positional `ztdf` | `--containerType tdf3` |

Per-SDK quirks become one line in the adapter rather than a shell workaround:
go's `mv "${3}.tdf" "${3}"` (`cli.sh:233`, "go helpfully adds a tdf extension"),
java's mtime-keyed `jar_help()` memo (`cli.sh:45–67`), js's `npx` prefix.

### Binary resolution

`install_go_release` and friends already know the exact invocation at install
time. Replace the runtime re-derivation with a descriptor written once into
`dist/<version>/`:

```json
{"sdk": "go", "version": "v0.31.0", "adapter": "go",
 "exec": ["go", "run", "github.com/opentdf/platform/otdfctl@v0.31.0"]}
```

That deletes the `.version` re-parse in all three shims, the three `cp` lines in
each `sdk/*/Makefile`, and `sdk/go/cli.sh:172–191` (the walk-up for
`pyproject.toml` containing `name = "xtest"` so it can `source test.env`).
`sdk/go/otdfctl.sh` collapses into a `PolicyClient` on the go adapter. Keep
`.version` readable for one release as a compat shim for the four pinning repos.

### The argv diff gate

No shell is deleted until its lane has proved the adapter emits byte-identical
argv. During A2/A4/A5 the harness runs both, logs
`{"sdk", "verb", "argv", "env"}` for each, and fails the job on any difference.
`xtest/test_sdk_commands.py` (17 tests) already pins the `XT_WITH_*` contract on
the Python side; the diff gate extends that to the shell's output side, which
nothing currently covers.

Snapshot row shape, one per (SDK, feature):

```json
{
  "sdk": "go", "feature": "hexless",
  "shell": {
    "kind": "min_version", "line": 83,
    "version_probe": {"argv": ["--version", "--json"], "jq": ".schema_version"},
    "awk": "{ if ($1 > 4 || ($1 == 4 && $2 >= 2)) exit 0; else exit 1; }",
    "min_version": "4.2.0", "comment_claims": "4.3.0",
    "comment_matches_code": false,
    "samples": [["4.1.0", false], ["4.2.0", true], ["4.3.0", true]]
  },
  "becomes": "MinVersion"
}
```

`samples` is what makes this a characterization test rather than a
transcription: it records the *answer* at representative versions, so an
adapter that reads the same source and computes a different result is caught
even if it copies the declared `min_version` faithfully.

## Edge Cases & Constraints

| Hazard | Handling |
| --- | --- |
| **`hexless` go gate — CONFIRMED BUG.** `sdk/go/cli.sh:83` compares `($1 > 4 \|\| ($1 == 4 && $2 >= 2))`, i.e. **≥ 4.2.0**, under the comment `# Schema version 4.3.0 introduced hexless`. java (`:109`) and js (`:72`) both use `($1 > 4 \|\| ($1 == 4 && $2 > 2) \|\| ($1 == 4 && $2 == 3 && $3 >= 0))` — exactly ≥ 4.3.0. go alone reports hexless support for a 4.2.x build. | Fix in A3 as `MinVersion("4.3.0")`. Skip counts will move; the PR must say by how much. Snapshot records both the code's answer and the comment's claim, so the fix shows as a deliberate one-row diff. |
| **`better-messages-2024` go gate — second divergence, previously unreported.** `sdk/go/cli.sh:117` comments "These appeared in go sdk 0.3.28" and gates on `$3 >= 18` → **≥ 0.3.18**. Same shape as `hexless`, found by the same table. | Fix in A3 as `MinVersion("0.3.28")`, called out alongside `hexless`. |
| **awk fails open on non-numeric versions.** POSIX specifies a string comparison when a field is not a numeric string. Verified against real awk: `main`, `dev`, and `v0.12.0` all satisfy every `$1 > 0` gate. Contradicts the `FORCED_SUPPORTS` docstring's claim that the shims "say no for precisely the unreleased builds a fix needs to be evaluated against" — for any SDK whose version probe does not emit a bare numeric triple, they say **yes to everything**. | `MinVersion` parses with a real semver comparison and treats a non-semver version as "newest" *explicitly*, matching today's effective behaviour rather than the docstring's. A2 must not change it silently. |
| **4 hidden argv-path probes.** `java:208` (`jar_help decrypt \| grep -q kas-allowlist` → selects `--platform-endpoint=$PLATFORMURL` over `=$PLATFORMENDPOINT`), `java:270` (`jar_help \| grep -q -- '--verbose'` → appends `--verbose`), `js:268` (`help \| grep autoconfigure` → appends `--policyEndpoint … --autoconfigure true`), `js:301` (`help \| grep 'from "/key-access-servers" endpoint'` → appends `--policyEndpoint` else `--ignoreAllowList`). | All four are recorded in `supports_matrix.json["argv_path_probes"]` with the gate they become. An adapter porting only the `supports` block emits wrong argv and A2's diff goes red — which is the point. |
| **`XT_WITH_KAS_ALLOWLIST` vs `XT_WITH_KAS_ALLOW_LIST`.** `tdfs.decrypt_command` writes the former; all three shims read the latter. Dead today: no functional test passes `kasallowlist=` / `ignore_kas_allowlist=`, and the only unit test that does (`test_sdk_commands.py:124`) asserts the Python spelling, so it can never catch the mismatch. | Not fixed here — fixing it turns a no-op into a live flag and changes behaviour. Record it; fix under its own ticket with a functional test. |
| **Env vars read but never written.** `XT_WITH_PLAINTEXT_POLICY`, `XT_WITH_ECDSA_BINDING`, `XT_WITH_DPOP_KEY` are consumed by the shims and set by nothing. `encrypt_command`'s `policy_mode` parameter is accepted and unused. | Adapters do not reimplement them. A2's argv diff is unaffected because they are never set. |
| **Four repos pin `opentdf/tests@main`.** Deleting a shim breaks any of them still invoking `cli.sh` directly. | Per-SDK staging; `.version` stays readable for one release; A3/A4/A5 each announce the deletion in the PR body. |
| **`gmac_root_rejected` has no CLI surface.** All three shims `exit 1` under a comment explaining there is nothing to grep for. | `Unprobeable(False)` carries the reason as data instead of as a comment, so it can be asserted on. |
| **No platform available during this work.** | The snapshot and its verifier are fully offline: they read `cli.sh` as text, model `awk` in Python (cross-checked against real `awk`), and drive `_uncached_supports` against stub shells. The one test that needs a real build skips per SDK when `sdk/<sdk>/dist/*/cli.sh` does not exist. |

## Out of Scope

The `otdf-adapter` package itself — `SdkAdapter`, the gate kinds, and
`SubprocessCliAdapter` — is DSPX-4791 and this ticket is stacked on it.
Restructuring `xtest/` into `src/xtest/` is DSPX-4793. Adapter discovery via
entry points is DSPX-4794; until then adapters are imported by path. Fixing the
`XT_WITH_KAS_ALLOWLIST` name mismatch and the unused `policy_mode` parameter are
behaviour changes and belong to their own tickets. No `cli.sh` is deleted in the
PR that lands this spec.
