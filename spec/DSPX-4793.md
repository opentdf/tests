# upstream(opentdf/tests): make xtest a buildable distribution (src layout, build-system, package data)

## Summary
Blocked by DSPX-4640. Upstream work in github.com/opentdf/tests.
Steps B1-B3. Turn xtest/ from a run-in-place test directory into an installable distribution, so downstream consumers can depend on it instead of vendoring it.
Whyxtest/pyproject.toml has no [build-system] table, and says so in a comment: "This is a test suite, not a distributable package. Use uv pip install -r pyproject.toml or uv sync for dependencies." There is nothing to uv add. Meanwhile the two sibling tools, otdf-sdk-mgr and otdf-local, are properly packaged (build-backend = "uv_build", src/ layout, [project.scripts]) — so the pattern to copy is already in the repo.
Consumers that want to run xtest against their own platform currently have to vendor the whole repo (submodule/subtree) and run with cwd == xtest/. Making it a real distribution removes that entirely.
Scopextest/
├── pyproject.toml            # + [build-system] uv_build
└── src/xtest/
    ├── __init__.py
    ├── tdfs.py abac.py otdfctl.py zipinspect.py sizes.py assertions.py audit_logs.py
    ├── fixtures/ perf/
    ├── plugin.py             # [project.entry-points.pytest11] xtest = "xtest.plugin"
    ├── data/                 # manifest.schema.json, extra-keys.json, golden/
    └── tests/                # test_*.py + __init__.pyB1 — src/xtest/ layout. Today's flat top-level modules (tdfs.py, conftest.py, test_*.py, no __init__.py outside fixtures/ and perf/) are the direct cause of the install blocker: installing them puts a bare conftest at site-packages root, which collides with a consumer's own conftest under importmode=prepend and raises ImportPathMismatchError. Packaging also collapses [tool.ruff.lint.isort] known-first-party from nine names to one. Largest diff, smallest risk — ship it alone with zero behaviour change.
B2 — kill the cwd coupling. SDK.__init__ hardcodes f"sdk/{sdk}/dist/{version}/cli.sh" (tdfs.py:671), all_versions_of joins "sdk" (tdfs.py:947), and load_otdfctl() probes sdk/go/dist/main/otdfctl.sh at conftest import time (conftest.py:669). Introduce XT_SDK_DIR (default ./sdk) and XT_ENV_FILE (default ./test.env), resolved in pytest_configure rather than at import. The shell-side half of this (sdk/go/cli.sh:174's walk-up for a pyproject containing name = "xtest") is removed for free by the adapter work.
B3 — package data. manifest.schema.json, extra-keys.json and golden/*.tdf move under src/xtest/data/ and are read via importlib.resources. test.env is generated, never shipped. setup-cli-tool/action.yaml is a composite GitHub Action and cannot live in a wheel — it stays at repo root.
Also fix herextest/pyproject.toml:7 declares license = { text = "BSD-3-Clause" }, which contradicts the repo LICENSE (BSD-3-Clause-Clear). Correct it as part of B1.
Acceptance criteria[ ] uv build in xtest/ produces a wheel.
[ ] uv run --with ./dist/xtest-*.whl pytest --pyargs xtest.tests passes from a directory that is not xtest/, with no ImportPathMismatchError.
[ ] No module reads a relative path at import time.
[ ] Data files resolve through importlib.resources, not open("manifest.schema.json").
[ ] The four repos pinning opentdf/tests@main still run green without changes.
[ ] license metadata matches the repo LICENSE.
