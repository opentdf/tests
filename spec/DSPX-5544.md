# per-PR cross-SDK partial decrypt through the NFS mount

## Summary
Add the DSPX-5543 NFS mount as a third source in DSPX-5117's
`test_partial_decrypt.py`, next to the local file and HTTP. Any SDK CLI whose
`partial_decrypt` is supported reads the mount as a plain path, so otdfctl is
covered without a URL input.

## Proposed Solution
- `SOURCES` gains `nfs`: `nfs_mount(FullFile(ct))` returns the path and the
  range server's log. Same range matrix and plaintext checks as `file` and
  `http`; it needs only `partial_decrypt`, so every SDK that supports it runs,
  otdfctl included.
- NFS cells use a 20 MiB + 112 KiB position-unique plaintext (`line_bytes`),
  so a whole-payload read overshoots the budget by far more than block
  rounding. Each cell mounts afresh, so the page cache never carries over.
- Read accounting: bytes served must not exceed head + covering segments +
  tail, each extent widened to 1 MiB (RSIZE) multiples, plus 3 MiB: Linux
  read-ahead (one RSIZE window) can run up to two windows past the last byte
  read. Each cell logs served bytes against the budget as a warning.
- The tampered-segment and tampered-root-signature cases also run through the
  mount (`TAMPER_SOURCES`).
- `XT_NFS_PARTIAL_REQUIRED=1` fails the session unless an `nfs` range cell
  passed; set with `XT_PARTIAL_DECRYPT_REQUIRED` in the default-ref lanes.

## Edge Cases & Constraints
- Full-file mode only: no dropped extents, no filler.

## Out of Scope
Sparse (dropped-extent) cells and segment regeneration (DSPX-5547).

## Acceptance Criteria
- [x] Same range matrix and plaintext checks through the mount.
- [x] Read accounting bound from the range server log.
- [x] Tamper cases through the mount.
- [x] Runs in per-PR CI on `ubuntu-latest`; fails if no pair executes.
