# upstream(opentdf/tests): otdf-adapter package — typed protocol + SubprocessCliAdapter

## Summary

`xtest` reaches every SDK through a hand-written bash shim. There are three of
them, 846 lines in total, and 388 of those lines — 46 percent — are a single
`supports` case statement written out three times with hand-rolled semver in
`awk`. The shims exist because `tdfs.SDK` has no vocabulary for an SDK other
than "one of `go`, `java`, `js`, and here is a directory where its `cli.sh`
lives".

This change introduces `otdf-adapter`, a sibling package to `otdf-sdk-mgr` and
`otdf-local`, holding a typed `SdkAdapter` protocol, frozen request objects, a
vocabulary for capability gates, and entry-point discovery. It lands exactly
one implementation, `SubprocessCliAdapter`, which builds the same argv and the
same `XT_WITH_*` environment as the code it replaces and execs the same
`cli.sh`. `tdfs.SDK` delegates to it. **No shell is deleted and no behaviour
changes.**

The value of this step is not that it removes anything — it removes nothing.
It is that the next three steps (transcribing the gate tables, writing native
adapters, deleting the shims) become individually reviewable, because each one
can be checked against a stub instead of against a live platform.

## Problem / Motivation

### The call stack is four layers, two of them lossy

```
test body
  → tdfs.SDK.encrypt(...)                typed Python
  → XT_WITH_* env dict                   lossy: every option becomes a string
  → cli.sh <verb> <src> <dst> <fmt>      lossy: four positional slots, nowhere for options
  → bash rebuilds argv                   per-SDK flag vocabulary, in shell, three times
  → otdfctl / java -jar / npx
```

`XT_WITH_*` is not a design. It exists because `cli.sh <verb> <src> <dst>
<fmt>` has four positional slots and nowhere to put an option, so options were
smuggled past the signature in the environment. There are ten such variables,
set at `xtest/tdfs.py:750,753,756,759,762` (encrypt) and `:828,830,832,834,836`
(decrypt), and read back across three shells.

Nothing type-checks across that boundary, and the untypedness is not
hypothetical:

> **A latent bug this change found and deliberately preserved.** `tdfs.py:834`
> writes `XT_WITH_KAS_ALLOWLIST`. All three shims read
> `XT_WITH_KAS_ALLOW_LIST` — `sdk/go/cli.sh:247-248`,
> `sdk/java/cli.sh:237-238`, `sdk/js/cli.sh:294-295`. The two names differ by
> one underscore, so the `kasallowlist=` option has never reached any SDK. The
> only caller of that keyword is the unit test, which asserts the Python-side
> spelling and therefore passes vacuously. A typed request object makes this
> class of defect a static error; a `dict[str, str]` never will.

### The capability layer is one concept in two languages, and the migration is already half-done

`tdfs.SDK._uncached_supports` (`tdfs.py:894`) opens with a Python `match` over
`(feature, self.sdk)` carrying nine hardcoded answers and a `case _: pass`
(`:895-932`), then falls through to `subprocess.check_call([self.path,
"supports", feature])` (`:934-945`). One of its own comments says the quiet
part: the answer lives in *this* repo's shell, not in the SDK's.

The shell half:

| Shim | Lines | `supports` block | Named feature arms |
|------|-------|------------------|--------------------|
| `sdk/go/cli.sh` | 259 | `:39-170` (132) | 15 |
| `sdk/java/cli.sh` | 275 | `:69-199` (131) | 16 |
| `sdk/js/cli.sh` | 312 | `:33-157` (125) | 15 |
| **Total** | **846** | **388** | **46** |

46 named arms answer 20 distinct features (plus three `*)` catch-alls). Each
arm is one of exactly three things:

- **A version comparison, hand-rolled in `awk`.** `--version --json | jq -re
  .sdk_version | awk -F. '{ if ($1 > 0 || ($1 == 0 && $2 >= 12)) exit 0; else
  exit 1; }'`, with the boundary expression rewritten from scratch each time.
  It is rewritten because there is nothing to reuse, and rewriting is where
  the mistakes are: `sdk/go/cli.sh:83` compares `$2 >= 2` under a comment on
  the line above that says *"Schema version 4.3.0 introduced hexless"*. The
  gate admits 4.2.
- **A help-text probe.** `"${cmd[@]}" help encrypt | grep target-mode`.
- **A constant**, `exit 0` or `exit 1`, sometimes with a comment explaining
  why.

Two further shapes exist but had no vocabulary, so they were spelled as one of
the above and lost information:

- **The SDK can answer natively.** `sdk/java/cli.sh:161-164` shells to
  `cmdline.jar supports dpop`. This is the right answer and the only arm that
  will not need transcribing — but it is indistinguishable in form from the
  arms that guess.
- **The capability is unprobeable.** Written as a bare `exit 1`, which the
  suite renders as `"{sdk} sdk doesn't yet support [{feature}]"`
  (`tdfs.py:892`) — the same message as "too old". A skip that cannot say
  whether the build lacks the feature or the harness cannot tell is a skip
  nobody investigates.

### The set of SDKs is closed

`sdk_type = Literal["go", "java", "js"]` (`tdfs.py:103`), `container_type`
(`:112`), and a 26-entry `feature_type` (`:117-207`) are closed `Literal`s in
the suite's own source. `xtest` is consumed by four repos that pin it at
`main` — `opentdf/platform`, `opentdf/java-sdk`, `opentdf/web-sdk`, and
`opentdf/otdfctl`. Each drives its own client and has its own reason to want a
cell in the matrix. None of them can add one without a PR to this repo.

## Proposed Solution

A new package, `otdf-adapter/`, sibling of `otdf-sdk-mgr` and `otdf-local` and
copying their shape exactly: `build-backend = "uv_build"`, `src/` layout, its
own `uv.lock`, its own `AGENTS.md` with `CLAUDE.md` symlinked to it, and its
own lane in `check.yml`.

```
otdf-adapter/
├── pyproject.toml              # [project.entry-points."otdf.adapters"] go/java/js
├── README.md / AGENTS.md
├── src/otdf_adapter/
│   ├── protocol.py             # SdkAdapter Protocol + request dataclasses
│   ├── gates.py                # gate vocabulary + one evaluator; tables empty
│   ├── registry.py             # entry-point discovery -> load_adapter(...)
│   ├── subprocess_cli.py       # the only implementation
│   └── descriptor.py           # reads dist/<version>/adapter.json
└── tests/                      # 60 tests, no SDK and no platform required
```

`xtest` consumes it as an editable path dependency declared under
`[tool.uv.sources]` in `xtest/pyproject.toml`.

**`protocol.py` imports nothing else in the package.** That is what lets a
consumer's adapter depend on the protocol without also depending on the
subprocess machinery it does not use.

**The strangler property is that the gate tables are empty.** `GATES` in
`gates.py` is `{}`, and `SubprocessCliAdapter.supports` consults it first and
falls back to `cli.sh supports <feature>` when there is no entry. An empty
table is therefore *exactly* today's behaviour, and the 46 arms can be
transcribed one row at a time, each reviewable against the bash it replaces,
rather than in a flag day.

**`tdfs.SDK` keeps its public surface.** `encrypt_command` and
`decrypt_command` keep their exact keyword signatures and their
`tuple[list[str], dict[str, str]]` return, because `fixtures/bench.py:363,374`
unpacks them as `argv, env = ...`. The constructor keeps raising
`FileNotFoundError("SDK executable not found at path: ...")`, because
`conftest.py:362,373` catches it to report an SDK that was named but never
installed. The nine-arm `match` in `_uncached_supports` is preserved verbatim
and still runs before the adapter is consulted; folding it into the gate
tables is the last step of the migration, not this one.

### Rejected alternatives

**Make the repo a `uv` workspace.** The natural way to share a sibling package
is a workspace, but workspace members cannot live outside the workspace root,
so this would mean moving `xtest/`, `otdf-local/` and `otdf-sdk-mgr/` under a
new root and rewriting every path in `check.yml`, `xtest.yml`, and the four
consuming repos' pins. A path source in `[tool.uv.sources]` gets the same
editable install for one stanza. Cost is one CI flag, documented below.

**Put `ecwrap` in `container`.** The suite has a pseudo-container
`ztdf-ecwrap`, which means "a ztdf, produced with an EC wrapping key". Keeping
it as a container value would mean every consumer of `container` downstream —
including SDK flag construction — has to know that one of the container names
is not a container. `simple_container` (`tdfs.py:658`) already exists solely
to launder it back into `"ztdf"` at each use site. The request objects split
it at the boundary instead: `container="ztdf"`, `ecwrap=True`.

**A base class instead of a `Protocol`.** An `SdkAdapter` ABC would force a
consumer's adapter to import this package at class-definition time and would
make the entry point a subclass check. Structural typing means a consumer's
adapter satisfies the protocol by having the right methods, and
`runtime_checkable` still allows `load_adapter` to verify what a foreign
factory returned.

**Fix the `XT_WITH_KAS_ALLOWLIST` misspelling here.** Tempting — it is a
one-character change — and rejected, because this change's entire safety
argument is that it is behaviour-identical by construction. Fixing a real
defect under cover of a refactor means the first live run has two independent
reasons to differ from the last one. It is preserved verbatim, recorded in
`KNOWN_SHIM_MISMATCH`, and left for a change where the matrix result *is* the
evidence.

## Inputs / Outputs / Contracts

```python
# otdf_adapter.protocol  -- imports nothing else in the package
DEFAULT_CONTAINER = "ztdf"
DEFAULT_MIME_TYPE = "application/octet-stream"

@dataclass(frozen=True)
class SdkVersion:
    raw: str
    sdk: str | None = None
    schema: str | None = None
    features: tuple[str, ...] = ()

@dataclass(frozen=True)
class EncryptRequest:
    src: Path
    dst: Path
    container: str = DEFAULT_CONTAINER
    mime_type: str | None = DEFAULT_MIME_TYPE
    attributes: Sequence[str] = ()     # normalised to a tuple in __post_init__
    assertions: str | None = None
    target_mode: str | None = None
    policy_mode: str = "encrypted"     # accepted, no shim consumes it
    ecwrap: bool = False
    ecdsa_binding: bool = False        # accepted, no shim consumes it

@dataclass(frozen=True)
class DecryptRequest:
    src: Path
    dst: Path
    container: str = DEFAULT_CONTAINER
    assertion_verification_keys: str | None = None
    verify_assertions: bool = True
    ecwrap: bool = False
    kas_allowlist: str | None = None
    ignore_kas_allowlist: bool = False

@runtime_checkable
class SdkAdapter(Protocol):
    name: str
    version_spec: str
    def encrypt(self, request: EncryptRequest) -> Path: ...
    def decrypt(self, request: DecryptRequest) -> Path: ...
    def supports(self, feature: str, container: str = DEFAULT_CONTAINER) -> bool: ...
    def version(self) -> SdkVersion: ...
```

`attributes` is normalised to a tuple on construction. A frozen dataclass with
a mutable default is a caller-owned handle into a value the caller believes is
immutable; `TestDeterminism` asserts that mutating the list you passed cannot
change a command already built from it.

**`supports` takes a container.** `cli.sh supports <feature>` cannot express
"supports assertions for ztdf but not for some other container", so today the
suite answers per-SDK and re-derives the rest at the call site. The parameter
is accepted and *cannot currently change the answer* — the shim has nowhere to
put it. It is in the signature now so that adding a per-container gate later
is a change to `gates.py`, not to every caller a second time.

```python
# otdf_adapter.gates  -- inert data; must not run a subprocess
MinVersion(minimum: str, field: Literal["sdk","schema"] = "sdk", reason: str = "")
HelpContains(subcommand: Sequence[str] = (), needle: str = "", ignore_case: bool = False)
Always(answer: bool, reason: str = "")
Delegate(feature: str | None = None)      # the SDK answers natively
Unprobeable(reason: str)                  # distinct from "too old"

Gate = MinVersion | HelpContains | Always | Delegate | Unprobeable
GATES: dict[str, dict[str, Gate]] = {}    # deliberately empty

def evaluate(gate: Gate, ctx: GateContext, feature: str = "") -> GateResult
def lookup(sdk: str, feature: str, tables=None) -> Gate | None
```

`GateResult` is `(supported: bool, reason: str)` with `__bool__`, so a skip
message can say *why* rather than only *no*. `MinVersion` uses
`packaging.version.Version`, which handles the `v` prefix and prereleases that
the `awk` form gets wrong; an unparseable or missing version answers no with a
reason naming which.

```python
# otdf_adapter.registry
ENTRY_POINT_GROUP = "otdf.adapters"
BUILTIN_ADAPTERS = ("go", "java", "js")
def available_adapters() -> dict[str, EntryPoint]
def load_adapter(name, version="main", sdk_dir=None, dist_dir=None) -> SdkAdapter
```

The three built-ins are registered as entry points in this package's own
`pyproject.toml` rather than special-cased, so the extension path is the path
the default run exercises and cannot quietly rot. They are *also* resolvable
without installed metadata, because a source checkout on `sys.path` has none.

```python
# otdf_adapter.subprocess_cli
class Command(NamedTuple):           # a two-tuple with names; bench.py unpacks it
    argv: list[str]
    env: dict[str, str]

class SubprocessCliAdapter:
    path: str                        # "sdk/<name>/dist/<version>/cli.sh", relative
    def encrypt_command(self, r: EncryptRequest) -> Command
    def decrypt_command(self, r: DecryptRequest) -> Command
```

`path` is relative because the suite logs it on every invocation and runs from
the `xtest` directory; an absolute path would make both the logs and the
golden argv machine-specific. It is **not** on the protocol — an adapter that
links an SDK as a library has no executable to name.

`descriptor.py` reads an optional `dist/<version>/adapter.json`
(`{sdk, version, adapter, exec[]}`) and falls back to the `cli.sh` layout every
build currently produces. A *missing* descriptor is normal; a *malformed* one
raises rather than falling back, because falling back would run a different
build than the caller asked for and report the result under the requested
version's name — the one failure mode a cross-version matrix cannot survive.

### CI

`check.yml` gains an `otdf-adapter` lane mirroring the two existing sibling
lanes. The `xtest` lane changes one flag: `uv run --frozen --no-build` becomes
`uv run --frozen --no-sync`, and the install step above it becomes `uv sync
--frozen --extra dev`. `--no-build` refuses any distribution without a wheel,
and an editable path install has none by design; the "nothing unlocked slips
in" guarantee moves one step earlier to the `sync`, where it also catches a
`pyproject.toml` edited without a re-lock.

## Edge Cases & Constraints

**A vacuous pass is the failure mode to design against.** The entire safety
argument is "byte-identical argv and env", and a characterization suite that
asserts the wrong thing proves nothing. Two specific traps:

- The suite must assert against a **stub `cli.sh` in `tmp_path`**, not a
  mocked adapter. Asserting that `tdfs.SDK.encrypt_command` returns what
  `SubprocessCliAdapter.encrypt_command` returns is a tautology; asserting the
  literal argv list and the literal env dict is not.
- The strongest available evidence is not a new test at all. It is running the
  **unmodified pre-change** `test_sdk_commands.py` against the refactored
  `tdfs.py`. That file cannot have been written to match the new
  implementation, because it predates it.

**The `kasallowlist` test passes for the wrong reason.** Because of the
underscore mismatch above, the existing assertion pins a variable no shim
reads. It is kept — pinning today's behaviour is the job — with a comment
pointing at `KNOWN_SHIM_MISMATCH` so the next reader does not think it is
verified end-to-end.

**Version probes are memoized, and must stay that way.** `java -jar
cmdline.jar --version` pays JVM startup per call; `sdk/java/cli.sh` grew its
own help cache for exactly this reason. `SubprocessCliAdapter` memoizes
`version()` and `help_text(*subcommand)` per instance.

**An unparseable version probe must not raise.** Branch builds print all sorts
of things to stdout. `version()` returns an `SdkVersion` with `raw` set and
`sdk=None`; a raising probe would turn a skippable cell into a collection
error.

**Command builders must stay pure.** No filesystem access, no environment
mutation, no caching, no I/O. It is what makes the golden-argv tests possible
and it is asserted directly.

**Environment overrides are merged over `os.environ`, not substituted for
it.** The shims source `test.env` and read `PLATFORMURL` / `CLIENTID` from the
inherited environment; handing them only the overrides would break every
invocation.

**`expect_error` stays in `tdfs.SDK.decrypt`, not in the adapter.** It selects
how the caller runs the command — capturing combined output from a run it
expects to fail — not what the command is. Same argv, different invocation.

## Out of Scope

Deferred to follow-up tickets, deliberately:

- **Populating the gate tables.** Transcribing 46 case arms is where the
  mistakes are, and it is its own reviewable change. This ticket lands the
  vocabulary so the transcription has something to be reviewed against.
- **Native adapters.** No `go.py` / `java.py` / `js.py` that drives `otdfctl`,
  `java -jar`, or `npx` directly. `SubprocessCliAdapter` is the only
  implementation here.
- **Deleting any `cli.sh`.** Not one line of shell is removed. The shims
  remain the sole execution path; only the code that calls them moved.
- **Opening the `Literal` types.** `sdk_type`, `container_type` and
  `feature_type` in `tdfs.py` are untouched, as is the `src/xtest/` layout.
- **Fixing `XT_WITH_KAS_ALLOWLIST`.** See the rejected alternatives above.
- **`policy_mode` and `ecdsa_binding` reaching an SDK.** They are on the
  request objects because callers pass them. No shim consumes them today and
  none is taught to here.
